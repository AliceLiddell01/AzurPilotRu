# Игровая геометрия, распознавание и безопасное нажатие

Игровые операции адресуют Azur Lane Global/EN на точно выбранном экземпляре MuMu. Через
[Agent CLI](../reference/agent-cli.md) доступны наблюдение известных ассетов, проверка
соответствия координат ввода, Dock roundtrip и самостоятельное обеспечение главного UI из выключенного окружения.

## Готовность главного UI

`game-ui-ready-observe` ничего не запускает, не подключает и не нажимает. Операция возвращает
классификацию экрана; `Ready` требует нескольких независимых положительных признаков главного меню,
положительного совпадения свободных центральной и левой областей поддерживаемого профиля,
доказанных отрицательных guards, свежего foreground Global/EN и полноэкранного viewport.
Подтверждение накапливается только на независимых новых кадрах с устойчивым размером.
Один баннер `Login successful!`, foreground или успешный ADB не доказывает готовность.

`game-ui-ready-ensure` под одной общей lease использует существующий MuMu/Android/game lifecycle,
затем `GameUiReadinessService`. Уже запущенное окружение переиспользуется. Правила состояний и
разрешённых переходов находятся в `catalog.json/readiness`, а ограничения времени и действий —
в Core. Возврат из обычного Dock, LOG IN существующей сессии и PRESS TO START выполняются через
`GameUiActionRunner`. Для конкретного окна загрузки игровых файлов обязательны одновременно
Update, текст `This update requires downloading` и Confirm. Подтверждение кнопки не является
универсальным разрешением на обновление клиента: иное содержание окна остаётся неизвестным.

Postcondition действия может быть началом известной загрузки либо новым игровым состоянием;
исчезновение кнопки само по себе недостаточно. Начало загрузки не завершает ensure: далее следуют
пассивное ожидание и отдельное устойчивое подтверждение Ready. Баннер успешного входа только
ожидается. Повтор одного и того же действия в одном flow запрещён; Unknown, отсутствие эффекта,
неизвестный guard, смена endpoint и отмена не порождают слепой tap/restart/rollback.
После доказанного старта из `Stopped` начальный нераспознанный экран может пассивно ожидаться
до общего UI deadline, пока впервые не появится поддерживаемое состояние. Он остаётся `Unknown`,
без выдуманного Loading и без ввода. Это не продлевает deadline и не увеличивает ожидание неизвестного
экрана после уже распознанного состояния. Для работающей игры такое расширенное начальное ожидание не включается.
Для пульсирующего PRESS TO START action может пассивно ожидать появление исходного признака
при доказанных SERVER/логотипе, отсутствии postcondition и всех guards. Неоднозначность/Unknown
немедленно запрещают ввод. После ограниченного ожидания всё равно требуются свежий Unique,
viewport и однократный GameTap; исчезнувшая надпись не заменяется координатой из старого кадра.

Нижняя полоса загрузки анализируется native ROI statistics без выдачи пикселей. Изменение метрики
показывает только визуальную активность, не процент или успешность загрузки. Неизменность ограничивает
ожидание, но не доказывает зависание сети. Общий deadline всё равно ограничивает активную загрузку.
Итог содержит последние ограниченные наблюдения, кадры, счётчики ожиданий и попыток ввода,
раздельные результаты lifecycle/UI и возможный частичный эффект.

### Граница профиля и неизвестные окна

Положительный clearance сейчас привязан к предоставленному варианту главного фона. Другой секретарь,
анимация, тема или перекрытие могут дать `Unknown`; пороги ради успеха не ослабляются.
Это сознательное ограничение покрытия, а не универсальный детектор отсутствия любых диалогов.
Состав неизвестного окна нельзя вывести из отсутствия Update/Confirm. Такой экран не считается
Ready и автоматически не закрывается. Отдельных согласованных оригиналов безопасных объявлений
пока нет: награды, соглашения, клиентское обновление, секреты и неизвестные ошибки требуют человека.

## Владельцы

- [Core/Game](../../src/AzurPilot.Core/Game/) содержит типы координат, сведения о происхождении кадра, однократное
  разрешение `GameTap` и общий `GameUiActionRunner`.
- [Windows/Game](../../src/AzurPilot.Windows/Game/) связывает существующий адаптер захвата снимков с
  нативным распознаванием. `NativeFrame` остаётся единственным владельцем полного RGB8-кадра.
- [Каталог](../../assets/game/catalog.json) владеет смысловыми ID, происхождением crops, вариантами,
  режимами сопоставления, ROI, порогами, безопасными областями и сроками действий.
- [C ABI](../../native/include/azurpilot_native_abi.h) владеет формой результата сопоставления и бюджетами.
- `AzurPilotOperatorService` разрешает точный endpoint и держит существующую межпроцессную аренду
  на протяжении полного сценария. Вложенные шаги аренду повторно не захватывают.

## Координаты и native поиск

`GameGeometry` отделён от диагностических `ScreenshotDiagnosticRegions`. Логическая система координат
описывает UI; физическое разрешение приходит из метаданных нативного кадра. Поддерживается точное
соотношение 16:9 в альбомной ориентации от 720p до 4K. Границы ROI округляются наружу, безопасной области — внутрь.
Обрезания области по границам кадра, автоматического вращения и догадок о letterboxing нет. Поддержка 8K не заявлена:
нынешние бюджеты декодера и проверенный диапазон геометрии для неё недостаточны.

OpenCV читает ROI через заголовок `cv::Mat` без копирования полного кадра. Масштабируется маленький
шаблон, а не снимок. Каталог кеширует только закодированные crops; временные нативные шаблоны и карта оценок
освобождаются в одном синхронном вызове. Декодер проверяет отдельный бюджет шаблона до выделения RGB.
Текущие плоские кнопки используют яркость, заголовок Dock — RGB. Для этих непрозрачных crops маска
не нужна. Добавление нового ассета требует проверки его собственных положительных и отрицательных
образцов; совместимость произвольных UI-версий не предполагается.

`Unique` требует достаточной корреляции, допустимой ошибки пикселей и отрыва от второго независимого кандидата.
`Absent`, `Ambiguous`, `GeometryRejected` и `TechnicalFailure` сохраняются отдельно. Оценка не является
вероятностью. Второй максимум ищется вне окрестности первого размером в половину шаблона по каждой
оси; соседние положения одного и того же элемента не считаются разными кнопками.
Официальная семантика метода: [OpenCV matchTemplate](https://docs.opencv.org/4.x/df/dfb/group__imgproc__object.html).

## Ввод и доказательство эффекта

Перед нажатием свежий исходный признак должен быть `Unique`, а независимый признак результата — `Absent`.
Все исключающие признаки перехода должны быть доказанно `Absent` до ввода и после него. В текущем
переходе кнопка подтверждения выбора кораблей исключает режим выбора: общий заголовок Dock сам по
себе не доказывает обычный Dock. Эта кнопка не имеет безопасной области ввода и никогда не нажимается. Проверяются
устройство, физические размеры, внутренняя безопасная область, возраст кадра по монотонным часам от начала захвата,
передний план Global/EN и полноэкранное окно Android. `dumpsys input` должен доказать одинаковые
логические/физические границы и размеры устройства для display 0; rotation согласуется с конфигурацией окна.
Неизвестный формат, конфликтующие области отображения, inset/app bounds, перекрытое окно или compat scaling
отклоняются. Shell input получает координаты текущего логического дисплея; поворот сенсорного устройства
повторно не применяется. Основание —
[AOSP InputShellCommand](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/services/core/java/com/android/server/input/InputShellCommand.java).

Только Core создаёт `GameTap`; адаптер Windows повторно проверяет срок и атомарно расходует разрешение.
Одно нажатие адресуется тем же поставляемым ADB и точным endpoint, с явным display 0. Произвольных XY через CLI нет.
Произвольный swipe пока не публикуется: у текущего проверенного сценария нет такого действия.

После нажатия новый захват должен начаться после завершения команды, принадлежать тому же устройству и
разрешению и независимо подтвердить новый признак с исчезновением исходного. Проверка ограничена
дедлайном и не повторяет нажатие. `Unknown`, отказ ADB и отмена сохраняют возможный частичный эффект.
Успех ADB не подтверждает переход. При отмене или отказе автоматический возврат не выполняется;
успешное открытие и подтверждённое возвращение отражаются отдельно.

Аренда координирует AzurPilot, но не посторонние инструменты ADB и действия пользователя. Проверка области игры
уменьшает окно гонки; аппаратной атомарности между наблюдением и вводом Android не предоставляет.

## Сопоставление с оригиналом

Предметный ориентир — `AzurPilot-private-Ru`, ветка `personal/stable`, а не её `main`.

| Механизм оригинала | Решение текущей реализации |
| --- | --- |
| `module/device/screenshot.py`: ориентация, интервал снимков, время жизни изображения | Сохранены проверка размеров/ориентации и свежесть. Захват остаётся в существующем адаптере Windows с нативным кадром; глобального уменьшения до 720p нет. |
| `module/base/button.py`: отдельные `area`/`button`, смещение ROI, luma и проверка цвета | ROI поиска и безопасная область ввода принадлежат данным; найденное смещение переносит безопасную область. Для разных crops выбраны luma/RGB и независимая проверка ошибки пикселей. |
| `module/base/template.py`, `utils.py`: масштабирование шаблона и варианты | Масштабируется только шаблон; варианты хранятся в каталоге. Общего снижения порога на другом разрешении нет. |
| `module/base/resource.py`: кеширование и освобождение ресурсов | Небольшой ограниченный кеш закодированных шаблонов и RAII временных нативных объектов; полного RGB-кадра в managed памяти нет. |
| `module/device/control.py`, `method/adb.py`: кнопка → координата → ввод Android | Безопасный центр однократного разрешения идёт через существующий поставляемый ADB и точный endpoint; случайные координаты и старый стек устройства не переносятся. |
| `module/ui/ui.py::ui_click`: appear → click → check | Одно нажатие и отдельные последующие наблюдения под общим дедлайном. Цикл повторных кликов/автоматического восстановления не переносится. |
| `module/handler/login.py::_handle_app_login`, `handle_app_login`, `app_start` | Свежие последовательные кадры, известные login-состояния, ограниченное ожидание, устойчивое подтверждение главного экрана. Generic popup confirm, сбор наград и restart/очистка данных не перенесены. |
| `module/ui/ui.py::is_in_main`, `ui_page_main_popups`, `ui_goto_main`; `page.py`, `ui_white/assets.py` | Главный экран и обычный Dock различаются по подтверждённым Global/EN white UI-ассетам. Остальная legacy-карта страниц и варианты UI не импортируются. |
| `module/handler/assets.py`: LOGIN/UPDATE/ANNOUNCE/RETURN | Назначение проверяется по пользовательским оригиналам. Автоматический Confirm разрешён только конкретной загрузке игровых файлов. Для остальных окон нужны отдельные исходники и правила. |
| `module/application/legacy_game_adapters.py::LegacyGameApplicationAdapter.login_to_main` | После переходов заново проверяются UI и foreground/viewport; сообщение об успешном входе не заменяет postcondition. |

Проверки и воспроизведение ассетов: [проверка игрового UI](../testing/game-ui.md).
