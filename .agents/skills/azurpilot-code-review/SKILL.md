# Независимое ревью AzurPilotRu

1. Установи repository, объект ревью, точные base/head/merge-base, staged/unstaged/untracked
   изменения и полный scope. Для PR прочитай фактические refs через GitHub; не угадывай PR по ветке.
   Найди исходную задачу и применимые инструкции через
   [INDEX](../../../.codex/context/INDEX.md). PR body — заявление автора, а не источник истины.
   Недоступные требования обозначь как ограничение.
2. Прочитай весь существенный diff, затем потребителей, соседние функции, boundaries, tests,
   manifests и обработку ошибок. Проверь происхождение дефекта сравнением с base: ранее существовавшее
   нарушение не выдавай за регрессию. Применяй [критерии](references/criteria.md) только к затронутым областям.
3. Запусти уместные штатные deterministic проверки по
   [verification](../../../.codex/context/verification.md). Read-only ревью не разрешает MuMu/Android
   mutation или игровые tap. Для отдельно порученной реальной приёмки используй
   [live-testing](../azurpilot-live-testing/SKILL.md), для визуального TUI —
   [tui-harness](../azurpilot-tui-harness/SKILL.md).
4. Перепроверь причинную цепочку каждого кандидата и объедини симптомы одной первопричины.
   Серьёзность, порог доказанности и итоговый статус имеют единственного владельца:
   [политика findings](references/findings.md). Не выдавай сигнал анализатора за доказанный дефект.
5. Дай findings по серьёзности, соответствие исходным требованиям, границы покрытия, выполненные
   проверки и ограничения. Отсутствие находок при существенном непокрытии не означает CLEAN.

## Диагностические файлы

Разовые скрипты, fixtures, логи и отчёты создавай в отдельном безопасном **системном TEMP вне checkout
и всех его worktrees**. Перед записью проверь фактический разрешённый путь TEMP и корни из
`git worktree list --porcelain`, включая junction/symlink. Если TEMP попал внутрь worktree, выбери
другой системный временный каталог или продолжай без записи, обозначив ограничение.
Не используй `.codex/local/` из live-testing для read-only ревью.

Помощники только читают и диагностируют: без изменения исходников и Git/GitHub state, без собственных
review engine, persistent finding store, индекса или обёртки Git/gh. Реальные project build/tests
используют штатные output paths. После работы удаляй только принадлежащие этому ревью временные файлы.
Среду выполнения команд определяет `AGENTS.md`; машинный вывод — через pipes.

## Другие владельцы

Само упоминание CodeRabbit не разрешает его запуск. Только отдельный положительный запрос
маршрутизируется в [coderabbit-review](../azurpilot-coderabbit-review/SKILL.md).
Сначала заверши собственный анализ; сравнение с внешними findings выполняй лишь по поручению и
с обозначением их происхождения. Самопроверку автора не называй независимым вторым ревьюером.

Ревью само по себе не исправляет файлы, не отправляет комментарии и не меняет PR. Если отдельно
поручены исправление и публикация, обычная процедура принадлежит
[git-workflow](../azurpilot-git-workflow/SKILL.md).
