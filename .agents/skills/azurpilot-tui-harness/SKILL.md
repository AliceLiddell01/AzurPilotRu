# Визуальная проверка продуктового TUI

Подготовка, команды, профили, безопасность и контракт свидетельств принадлежат
[`docs/testing/tui-harness.md`](../../../docs/testing/tui-harness.md).

1. До визуальной правки собери текущий EXE и сохрани исходный снимок нужного состояния через
   поддерживаемый сценарий либо управляемую сессию. Выбери проверки и размер по изменяемому поведению.
2. Выполни одну логически целостную правку, собери App и открой **новую** ConPTY-сессию. Изменившийся
   EXE/DLL нельзя проверять старой сессией. Не заменяй продуктовый EXE тестовым рендерером.
3. Получи новый PNG/cells/evidence. Проверь утверждения по ячейкам, фактические цвета,
   синхронизацию, доступность шрифта и размеры. `BLOCKED` не превращай в `PASS` ожиданием наугад.
4. Самостоятельно открой PNG доступным image-viewing инструментом. Запиши визуальный признак,
   путь/идентичность сборки и отдельное визуальное заключение `PASS/FAIL/BLOCKED`. Если инструмент не
   принимает изображение, осмотр `BLOCKED`: существующий PNG или текст ячеек не доказывают визуальный
   осмотр. Harness не регистрирует осмотр и не меняет `visualAssessment` в машинном отчёте.
5. Сопоставь исходное состояние, исправление и результат до следующей визуальной правки. Не затирай
   предыдущие снимки. После серии запусти `verify.ps1` и релевантные тесты продукта.
6. Закрой принадлежащие сессии. В отчёте различай детерминированные, браузерные и физические свидетельства.

Для изменений, где важен именно рендеринг реального Windows Terminal (схема, шрифт, DPI или физическое
поведение ввода), либо при прямом запросе физической проверки, дополнительно пройди отдельный маршрут
`physical` по [разделу «Цвет и граница Windows Terminal» документации](../../../docs/testing/tui-harness.md#цвет-и-граница-windows-terminal).
ConPTY-снимок не заменяет физические свидетельства Windows Terminal.

По умолчанию safe запрещает дочерние процессы и изменения состояния продукта. `--providers read-only`
разрешает настоящее inventory без изменения состояния при закрытой продуктовой политике. Live environment
запускай в Harness только при текущем явном разрешении точного экземпляра; его возможности ограничены подготовкой
окружения и возвратом исходного состояния. Это ограничение Harness не запрещает уместную live-приёмку
через production Agent CLI по прямому поручению пользователя через
[live-testing](../azurpilot-live-testing/SKILL.md); точный экземпляр, предварительные наблюдения, постусловия
и восстановление описаны в [документации Agent CLI](../../../docs/reference/agent-cli.md) и
[Android acceptance](../../../docs/testing/android-acceptance.md).
Не запускай дополнительные агенты при запрете пользователя. Не объявляй xterm PNG подтверждением
поведения физического Windows Terminal.
