# Транспорты снимков: agent-critical контракт

- Единственный production-владелец захвата — `ScreenshotCaptureRouter` за `IAndroidScreenshotHost`.
  Не создавай второго владельца захвата, отдельный путь кадров для game UI/Dock/Debug или каталог координат.
- Каждый транспорт отдаёт проверенный RGB8 `NativeFrame` с provenance exact identity и временем захвата.
  Пиксели не проходят PNG round-trip и не копируются в C#; ADB-only факты остаются в `AdbPngCaptureFacts`.
- Успешный вызов ≠ новый кадр ≠ визуальное изменение ≠ доказанное постусловие. Повтор кадра потока
  (scrcpy) не считается свежим.
- `auto` без калибровки для отпечатка target — ADB. Калибровку пишет только `capture-benchmark` после
  доказанного главного экрана до и после. Явный метод не подменяется; откат `auto` всегда наблюдаем.
- `UNSUPPORTED` — наблюдённая неприменимость на этом target, не общий отказ; глобальные заглушки запрещены.
- Helper-ы: только закреплённые зависимости с проверкой SHA-256, target-scoped `adb -s`, слушатели только
  на loopback, shell-токены через белый список, остановка только своего PID по маркеру, журнал ресурсов до
  использования. Запрещены `pkill -f`, изменение глобального ADB-сервера, загрузка бинарников во время работы.
- `nemu_ipc`: DLL только из обнаруженной установки MuMu, экземпляр по exact identity, вызовы с тайм-аутом.
  Native stdout изолирован в Agent CLI; не возвращай вывод native-компонентов в stdout.
- Измерения не вводят в игру: combat-фаза только после ручного входа пользователя и кода из normal-фазы;
  собственное сообщение агента не является подтверждением. Отчёты — только в игнорируемом
  `.codex/local/reports/`, без кадров.
- Подробности: [`docs/architecture/screenshot-transports.md`](../../docs/architecture/screenshot-transports.md).
